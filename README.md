# music-workflow

**从「一句帮我写歌」到「番茄平台发布成功」的 AI 音乐自动化生产线。**

**妙响（抖音音乐创作实验室）**生成音乐 → 自动编辑导出并下载 → 自动生成 1440×1440 封面
→ 自动上传番茄音频创作平台（填表 + 独家授权 + 跳转授权）→ 停在电子合同签署页，
你本人签完即发布成功。

- **多账号通用**：不内置任何人的账号、手机号、Cookie。每个人用**自己的账号**跑自己的流程。
- **跨平台**：Windows / macOS / Linux 均可（浏览器清理逻辑已做跨平台处理）。
- **断点续传**：上传中途断网，恢复后自动接着传，不用从头再来。
- **1 份歌词出 2 个版本**：妙响平台规则，两版自动区分为「歌名」/「歌名（动听版）」。

> **生成端已换**（2026-09 起）：早期用 MiniMax 网页端，现改用**妙响**。
> MiniMax 代码保留为历史备选，当前流程请走妙响。

## ⭐ 哪些步骤需要人参与？

这是最常被问的问题。整条流水线里**只有 4 个环节需要你动手**，其余全自动。

| # | 环节 | 谁做 | 频率 | 说明 |
|---|---|---|---|---|
| 1 | 安装依赖 | 🧑 人 | **一次性** | `pip install` + `playwright install chromium`，约 2 分钟 |
| 2 | 首次登录妙响 | 🧑 人 | **一次性** | 用**抖音账号**登录。**登录态存系统每用户私有目录 `%LOCALAPPDATA%/music-workflow/profiles/douyin`（由 `scripts/paths.py` 解析，绝不在 skill 内）**，之后长期自动免登 |
| 3 | 首次登录番茄 | 🧑 人 | **一次性** | 同上，登录态存 `%LOCALAPPDATA%/music-workflow/profiles/profile_fanqie` |
| 4 | 写歌单和歌词 | 🧑 人 | 每批歌 | 这是创作部分，当然得你来（`tasks.csv` + `lyrics/*.txt`） |
| 5 | **签署电子合同** | 🧑 人 | **每批一次** | 需你本人收**短信验证码**完成签署。**签完 = 发布成功** |
| — | 生成音乐 / 编辑导出 / 下载 / 做封面 | 🤖 全自动 | — | 点生成、等出歌、导出、存库、出封面 |
| — | 番茄填表（6 项） | 🤖 全自动 | — | 音频 / 歌词 / 歌名 / 词曲·制作人·歌手 / 封面 / AI 类型 |
| — | 第一步下一步、第二步授权签约 | 🤖 全自动 | — | 独家授权 + 签约身份「个人」+ 确认签署 + 跳转授权 |
| — | 防重复发布记录 | 🤖 全自动 | — | 签完自动写入 `published.json`，下次自动跳过 |

> **关于登录态**：Cookie 一般能维持数周到数月。过期后脚本会提示，重跑一次 `--login` 即可，
> 不需要重新配置任何东西。
>
> **关于第 5 步**：电子合同涉及法律责任，必须由本人收验证码签署，任何自动化都不应代劳。
> 脚本会一直把浏览器开着等你（最多 30 分钟），签完自动记录。

## 用 AI 助手调用时的协作方式

如果你是通过 AI 助手（WorkBuddy / Claude 等）使用本 skill，它会遵守四条纪律：

1. **先问歌词谁写** —— 不会默认代劳，也不会默认甩给你。会问清是「你自己写 / 它代写 / 混合分工」。
   若由它代写，**每次动笔前都会先研究番茄音乐 APP 热歌榜的前十首**，学它们的创作思维模式与创作风格，
   洞察听众情绪需求，再结合番茄听众画像（下沉市场，80 后 / 70 后为主）创作 —— 而不是凭感觉写。
   每期研究都会追加回档案，越用越准。

   ```bat
   python fanqie_rank.py --rank 热歌榜 --limit 50          :: ① 采番茄音乐 APP 官方热歌榜 → <workdir>/charts/
   python fanqie_lyric.py --top 10 --rank 热歌榜            :: ② ★ 把前十首歌词拉下来拆解五层 → <workdir>/study/
   python fanqie_recipe.py --ranks 热歌榜,80后热歌,90后热歌  :: ③ ★ 出「创作配方卡」→ <workdir>/study/
   ```
   然后 **④ 回答配方卡第七节的「听众情绪需求四问」**（不答完不许开写）→ **⑤ 读历史档案 + 撞名黑名单**
   → **⑥ 追加写回 `HOT_SONG_RESEARCH.md`，才动笔**。

   > **★ 重点在第 ②③ 步。** 用户明确纠正过两次：
   > *「不是要你收集数据研究，是要研究歌曲的**创作思维模式和创作风格**，数据没什么好研究的」*；
   > *「创作之前要研究学习番茄音乐**热歌榜的前十首**，收集灵感并学习创作思维模式和创作风格，
   > 创作**符合平台受众人群**的爆款歌曲，能**挖掘洞察听众用户的情绪需求**，产生情感共鸣。」*
   >
   > 榜单只回答「哪首火」，**拆解才回答「它凭什么火」**，**配方才回答「你这首该怎么写」** ——
   > 拆解出的是**指标**（行数 / 重复几次 / 韵脚），配方把指标压成**参数**
   > （写几行、副歌几行、整块重复几次、歌名几个字、韵脚挑哪几个）。
   > **指标不能直接下笔，参数才能。**
   >
   > 拆解样本取的是番茄**在播版本**的歌词（详情页 `novelfm.com/music/<作品ID>` 全文直出，不是第三方歌词站），
   > 所以拿到的是「平台正在推的那个版本」的真实写法，五层 = 结构 / 记忆点 / 句式 / 韵脚 / 意象。
   >
   > ⚠️ 详情页**不含**作词作曲署名——拆解只覆盖「怎么写」，不覆盖「谁写的」；
   > 曲风标签改用第 ① 步榜单自带的**官方 `tags` 字段**（比推断准）。
   >
   > **为什么第 ① 步必须是番茄自己的榜**：听众在番茄，锚就得打在番茄身上。
   > **数据源选错不是「不够精确」，是「结论相反」** —— 实测翻车了两次，教训是叠加的：
   > ① 用**第三方榜**（搜狐/酷狗/歌曲吧）→ 得出「国风是**次要**题材」；
   > ② 换**番茄网页版** → **反转**成「国风是**第一大**题材」；
   > ③ 再换**番茄 APP 官方榜（现行口径）** → 又修正为「**流行/情歌/伤感/轻柔/DJ 才是主盘**，
   >    国风不在标签前列」。
   > 两条教训：**锚要打在番茄身上**；**口径要一致（网页版人工归类 ≠ APP 官方标签），
   > 换数据源后旧结论必须重估。**
   >
   > ✅ **第 ① 步用的是番茄音乐 APP 官方榜（不用抓包、不用登录）。**
   > 2026-09-21 打通 APP 自己的接口（`aid=8661` / `FmMusic`），拿到的是
   > **你在 APP「排行榜」里看到的同一份数据**：
   > - **10 个官方榜**：热歌榜 / 抖音榜 / 飙升榜 / 经典榜 / 70后热歌 / 80后热歌 / 90后热歌 / 00后热歌 / 车载热歌 / 运动热歌
   > - 每榜 **50 首**，带**平台自己的名次 + 涨跌幅 + 真实播放量 + 收藏数 + 官方曲风标签**
   >
   > `python fanqie_rank.py --list-ranks` 看全部榜；`--rank all` 全采。
   >
   > ⚠️ **网页版 ≠ APP，差距很大**（实测：网页版 199 首与 APP 热歌榜 50 首
   > **歌名交集 = 0 首**）。网页版没有榜单页（只有首页「热门歌曲」），
   > 所以 `fanqie_chart.py`（网页版）**已降级为兜底**，不用它当榜单。
   > 「APP 榜需手机抓包」这个旧结论**已作废**。
2. **人工环节主动提醒** —— 登录、短信验证码、签合同这些环节会**提前预告 + 说清在哪个窗口点什么**，
   不会让脚本在后台空转而你完全不知情。
3. **搞不定就请你教它** —— 同一环节连续失败会立刻停下，给你**保姆级手动步骤**；
   你手动做一遍把过程回传（截图 / 每一步点了什么 / 页面文字），
   它学完写入 `references/LEARNED.md` 和 `config.json`，下次这里就自动处理了。
4. **不许自证** —— 说「发布成功」之前，它会用 `verify_published.py`
   去番茄后台**只读核对**一遍作品列表（状态 / 作品 ID / 创建时间），
   而不是拿日志或截图当证据。**嘴上说成功不算数，后台有记录才算。**

## 快速开始

### 1. 装依赖

```bash
pip install -r scripts/requirements.txt
playwright install chromium      # ⚠️ 这步别漏，否则浏览器起不来
```

> 无 Python？先装 [Python 3.9+](https://www.python.org/downloads/)（3.13 实测通过，只用标准库 + playwright/pillow）。
> Windows 用户若 `playwright` 命令找不到，用 `python -m playwright install chromium`。

### 2. 初始化你的工作目录

```bash
python scripts/init_workdir.py D:/my-music
cd D:/my-music
```

会生成一套**完全干净**的目录：脚本、配置、空的曲库 / 歌词目录。登录态**不在这里**，
而存在你系统每用户私有目录 `%LOCALAPPDATA%/music-workflow/profiles/`（每用户独立、不在 skill 内）。
每个人的工作目录互相独立，互不干扰。

### 3. 登录两个平台（各一次，之后全自动）

```bash
python miaoxiang.py --login       # 浏览器打开，用你的「抖音账号」登录 妙响
python fanqie_upload.py --login   # 浏览器打开，用你的账号登录 番茄
```

登录成功、看到对应页面后脚本会自动退出（妙响这条是关掉浏览器窗口即完成），
登录态保存在你系统每用户私有目录
`%LOCALAPPDATA%/music-workflow/profiles/douyin`（妙响）与 `.../profile_fanqie`（番茄）
（不在 skill 文件夹内，因此拷贝 skill 不会带走你的账号）。

> 若遇到「点了登录没反应 / 弹窗一闪就消失」，那是平台风控识别了自动化浏览器：
> ```bash
> python login_check.py douyin    # 妙响；或 fanqie，带反自动化检测 + 自动截图诊断
> ```

### 4. 写歌单和歌词

编辑 `tasks.csv`（照着里面的示例行格式写）：

```csv
歌名,风格描述,歌词文件,生成数量,纯音乐
我的第一首歌,治愈 流行 钢琴 72BPM 男声 温暖 希望,我的第一首歌.txt,2,否
```

歌词放到 `lyrics/我的第一首歌.txt`。

> 以 **`示例-`** 开头的行是格式示范，**不会真的生成**（专门做了跳过，避免你一跑就白烧额度）。
>
> **关于「生成数量」列**：妙响平台的规则是「**1 份歌词点 1 次生成，固定产出 2 个版本**，
> 数量不可改」，所以这一列**不起作用**。想要几首就写几份不同的歌词。
> 两个版本会自动区分命名：第 1 版 = `我的第一首歌`，第 2 版 = `我的第一首歌（动听版）`。

### 5. 生成音乐

```bash
python miaoxiang.py --gen --model "Sway v5.5" --download-mode both
```

自动：填歌词和曲风 → 选模型 → 点生成 → 等出歌（约 5–6 分钟）→ 逐版走「编辑导出」→ 下载
→ 生成封面 → 存进 `library/`。
每首歌得到 `audio.mp3` + `cover.png` + `lyrics.txt` + `meta.json`。

> **两个参数说明**：`--model` 必填且**必须显式写 `Sway v5.5`**（页面默认是「自动」，不写会选错）；
> `--download-mode both` 表示两个版本都下载，只想下第一版用 `first`。
> 生成前脚本还会再问你一次下载策略，按提示选即可。

### 6. 上传番茄

```bash
python fanqie_upload.py
```

自动：扫描 `library/` 里**还没发过**的歌 → 逐张填表 → 第一步下一步 → 独家授权 → 签约个人
→ 确认签署 → 等合同生成 → 点「跳转授权」→ **停下等你签合同**。

### 7. 签合同 = 发布成功 ★

浏览器会保持打开，你收验证码签完电子合同就算发布成功。
脚本检测到「签署成功 / 签署完成 / 签约成功 / 合同已生效」等字样后，自动把这首歌写进
`published.json`，**下次再跑就不会重复发**。

若自动检测没生效，手动补记：

```bash
python fanqie_upload.py --mark-published 我的第一首歌-01,我的第一首歌-02
```

### 曲库目录名怎么定的（`versions_ledger.json`）

`library/` 里每首歌的目录名由**这首歌最终几版**决定，记在 `versions_ledger.json`：

| 这首歌最终几版 | 目录名 |
|---|---|
| 单版 | `<歌名>` |
| 双版 | `<歌名>-01`、`<歌名>-02` |

这个账本**不用你手工维护** —— `miaoxiang.py` 每次入库会自己登记。
它的作用是防止一个坑：同一首歌如果**分两次下完**（第一次 `--gen` 下第 1 版、
第二次 `--redownload` 补第 2 版），两次的下载策略可能都是 `first`，
早期版本会因此把两版都算成「裸歌名」目录 → **第 1 版被第 2 版覆盖掉**。
现在有了账本 + 写盘护栏（目标已有不同音频就让位到 `-NN`），不会再覆盖。

## 常见问题

| 现象 | 解决 |
|---|---|
| 一直等「发布」按钮 | 番茄**没有发布按钮**，终点是签电子合同。脚本已停在合同页，签完即可 |
| 签完合同脚本还在等 | 签署页**签完会自己跳走**（回登录页），「签署成功」字样随之消失。脚本已内置判据（签署页消失/变登录页即算成功）；万一没识别到，用 `--mark-published` 手动补记 |
| 提示找不到卡片 / 下载的不是同一首歌 | 妙响资产页的卡片要按**签名**认。先跑 `python miaoxiang.py --list-cards`（只读、零额度），把签名抄进 `--redownload --card "签名=歌名"` 显式指定，别用「取最新 N 张」 |
| 生成完的歌没进 library | 别重新生成（浪费额度）。用 `--list-cards` 找到卡片，再用 `--redownload --card ...` 补下载入库 |
| 点了登录没反应 | 平台风控。用 `python login_check.py <平台>`（妙响用 `douyin`），带反自动化检测；确认没别的 Chrome 占着同 profile |
| 上传中途断网 | 不用慌，脚本带断点续传，联网后重跑即可，已传好的会自动跳过 |
| 封面不合规 | 番茄要 PNG、≥1440×1440、≤10MB，脚本生成的就是 1440×1440，别手改后缀 |
| 想只发某几首 | `python fanqie_upload.py --songs 歌名-01,歌名-02` |
| 想重发已发过的 | 删掉 `published.json` 里对应记录 |
| **歌太多把 C 盘塞满了** | 一条命令换盘：`python miaoxiang.py --set-workdir "D:\music-workflow"`。以后生成/上传/核对全部自动跟着走，下载中转也一起挪（不再占系统临时目录）。已攒的歌用 `python migrate_library.py --to "D:\music-workflow"` 搬过去，**只复制不删除**，核对无误再 `--purge-only` |
| 删完发现 C 盘**没腾出空间** | 正常：**回收站也在 C 盘**，扔进回收站只是「搬家」不是「腾空间」。加 `--empty-bin` 才真正释放：`python migrate_library.py --to "D:\music-workflow" --purge-only --empty-bin`（只清本次那几条，不动回收站里其它东西） |
| 换盘后上传脚本说「没有待发布的新歌」 | 说明上传端没认到新位置。`fanqie_upload.py` / `verify_published.py` 已同步支持该设置；若仍不对，用 `--workdir` 显式指一次 |
| **旧工作目录占着几个 G，想清掉** | 旧目录里的 `profile*`（历史登录态）动辄几百 MB，是**纯残值** —— 当前登录态在 `%LOCALAPPDATA%/music-workflow/profiles/`，不在工作目录里，所以删了**不用重新登录**。<br>⚠️ 但**分两步**：① 删目录 → ② 必须再清回收站 `python purge_bin.py --from-report "D:\music-workflow" --yes`，否则空间一点不释放。<br>⚠️ 删除命令要**在前台运行**，批量删除的授权提示只在会前台弹出来 |
| 删完发现 C 盘**没腾出空间**（第二遍） | 除了回收站的原因，还有一层：WorkBuddy 主机会把脚本里的删除操作**自动改道到回收站**（`shutil.rmtree` 也只是「搬家」）。所以「删了」和「腾出空间」是**两件事**，中间必须夹一步清回收站。判据永远看磁盘实测差值 |
| **`--gen` 报 `FileNotFoundError: '<工作目录>\config.json'`** | 妙响**不读**这个文件（它只服务已停用的 MiniMax 备选端），缺它不影响运行。已修：读不到就按默认值继续。若你也想补齐这个文件，从 skill 的 `scripts/` 拷一份到工作目录即可 |
| **搬到新盘后 `--gen` 就报上一条** | 老版本的 `migrate_library.py` 建新工作目录时只带 `tasks.csv`/`lyrics/`，**漏了 `config.json`**。已修：现在搬目录会连 `config.json` 一起带过去（源目录没有就从 skill 里兜一份） |
| **核对脚本报 `TargetClosedError ... launch_persistent_context`** | 上传脚本跑完**故意保持浏览器打开**，占着 `profile_fanqie`，而核对脚本用同一个登录态目录 → 起不来（那行 chromium 日志是乱码，看不出真因）。**先清理再核对**：`python browser_utils.py` → `python verify_published.py` |

<details>
<summary><b>关于弹窗：脚本是怎么自动处理的</b></summary>

网站不定时弹浮层（活动公告 / 新功能引导 / 会员推广 / 额度提醒），不关掉就点不动任何按钮。
`popup_guard.py` 会自动按「先礼后兵」的顺序处理：

1. 点弹窗里的 × 关闭按钮（32 种常见写法：antd 的 `.ant-modal-close`、`aria-label='close'` 等）
2. 点弹窗底部的主按钮（番茄的封面裁剪弹窗就是这种，文案可能是「确定 / 保存 / 完成」）
3. 点**确认类**文字按钮（我知道了 / 确定 / 好的 / 保存 / 完成 …）
4. 点关闭类文字按钮（取消 / 以后再说 …）
5. **兜底**：挡路浮层右上角的小图标（连 close 类名都没有时，按位置和 ❌ 符号认）
6. 按 Esc
7. 最后手段：删掉挡路的整屏遮罩（**默认关闭**）

**它是怎么认出弹窗的**：光靠 class 名字猜容器注定有漏网的（当年 MiniMax 的容器是
`section.responsive-modal z-[1050]`，不在任何标准名单里）。所以除了白名单，
凡是「固定定位 + z-index≥100 + 覆盖四成以上屏幕」的元素一律也算作用域——
**靠"它挡住了屏幕"这个行为识别，跟它叫什么名字无关**。

**为什么优先点「确认」而不是删遮罩**：点确认走的是页面自己的正常关闭流程，弹窗会自己关掉，
页面状态也保持一致。删遮罩是绕过页面逻辑的粗暴做法，可能连带干掉需要你看一眼的重要弹窗
（额度提醒、验证提示、授权确认），反而影响后续步骤。

**★ 安全红线：关闭按钮只在可识别的弹窗容器里找，绝不扫描整个页面**
（`scan_whole_page` 默认 `false`，不要改成 `true`）
上传页的「歌手名 / 词作者 / 曲作者 / 制作人」是标签式输入框，每个已填好的标签旁边
也有一个 × —— 那是**删除内容**用的，跟"关弹窗"的 × 长得一模一样。
扫描整个页面会把它们一起点掉（这个 bug 真实发生过）。现在靠"是否在弹窗容器内"来区分，
另有一份黑名单兜底，且含「删除 / 移除 / 清空」等词的按钮一律不点。

想确认它工作正常，跑一次自检（真起 chromium 真点一遍）：

```bash
python test_popup_guard.py     # 21 项自检，含"已填内容不被误删"等关键回归
```

## 隐私与安全

- ✅ 仓库里**不含任何人的账号、手机号、Cookie、登录态**——登录态本就存在你系统每用户私有目录
  `%LOCALAPPDATA%/music-workflow/profiles/`（Windows）/ `$XDG_CACHE_HOME/music-workflow/profiles/`

- ⚠️ 如果你要备份/迁移登录态，只备份上面那个**每用户私有目录**即可，**不要把它塞回 skill 文件夹**；
  仓库自带的 `.gitignore` 也仍排除 `profile*/`、`storage_state*.json`，作为双重保险。
